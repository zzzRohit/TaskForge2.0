# TaskForge Test Credentials

These credentials are fake development-only accounts created by the Prisma seed script. Do not use them in production.

Run the seed from the repository root:

```bash
bun run --cwd packages/db prisma:seed
```

The seed does not delete existing data. It updates the password and name of these test users, creates missing memberships and boards, and reuses matching organizations and boards.

## Authorization Scenarios

The backend sets an HTTP-only `token` cookie on sign-in. Keep that cookie when making the following requests.

Sign in as any seeded user:

```bash
curl -i -c cookies.txt -H "Content-Type: application/json" \
  -d '{"email":"owner@taskforge.test","password":"OwnerPass123!"}' \
  http://localhost:5000/api/auth/signin
```

Replace `<organizationId>` and `<boardId>` with IDs from your seeded database.

### OWNER

Use `owner@taskforge.test` in Alpha or Beta. An OWNER should be able to access organization resources and pass the stricter board-management middleware:

```bash
curl -b cookies.txt http://localhost:5000/api/organizations/<organizationId>/boards
curl -b cookies.txt -X PATCH \
  -H "Content-Type: application/json" \
  -d '{"title":"Updated by owner"}' \
  http://localhost:5000/api/organizations/<organizationId>/board/<boardId>
```

### ADMIN

Use `admin@taskforge.test` in Alpha, `admin2@taskforge.test` in Beta, or `admin@taskforge.test` as the OWNER in Gamma. An ADMIN should be allowed by the stricter board-management middleware in the organization where they are an ADMIN.

```bash
curl -b cookies.txt -X DELETE \
  http://localhost:5000/api/organizations/<organizationId>/board/<boardId>
```

### MEMBER

Use `member@taskforge.test` in Alpha or Gamma, or `member2@taskforge.test` in Beta. A MEMBER should pass organization membership checks for read access but should receive `403` from routes protected by `boardMiddleware` for board management.

```bash
curl -b cookies.txt \
  http://localhost:5000/api/organizations/<organizationId>/boards
```

A member should be rejected when accessing an organization they do not belong to. For example, User 5 must receive `403` for an Alpha organization ID.

## Current Route Middleware Note

The current board routes use `organizationMiddleware` for all board endpoints. They do not currently attach `boardMiddleware`, so a MEMBER may be able to reach the update and delete handlers after passing the organization membership check. To enforce the OWNER/ADMIN rule for mutations, add `boardMiddleware` to the PATCH and DELETE routes after `organizationMiddleware`.
